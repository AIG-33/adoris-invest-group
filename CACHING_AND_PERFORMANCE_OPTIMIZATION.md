# Кэширование и оптимизация производительности

## ✅ Реализованные оптимизации

### 1. Кэширование главной страницы (критически важно)
**Файл:** `next.config.js`

```javascript
{
  source: '/',
  headers: [
    {
      key: 'Cache-Control',
      value: 'public, s-maxage=60, stale-while-revalidate=120'
    }
  ]
}
```

**Что это дает:**
- `s-maxage=60`: CDN/Vercel кэширует страницу на 60 секунд
- `stale-while-revalidate=120`: Показывает кэшированную версию, обновляя в фоне до 120 секунд
- Работает вместе с ISR (`revalidate: 300`) для оптимальной производительности

### 2. Кэширование статичных страниц
Добавлено кэширование для:
- `/products` - каталог товаров
- `/product/:path*` - страницы товаров

### 3. Долгосрочное кэширование статических ресурсов
- `/_next/image` - изображения Next.js: `max-age=31536000` (1 год)
- `/_next/static/:path*` - статические файлы: `max-age=31536000` (1 год)
- `/fonts/:path*` - шрифты: `max-age=31536000` (1 год)

### 4. Оптимизация изображений
**Уже реализовано:**
- ✅ Использование `next/image` для всех изображений
- ✅ Автоматическая оптимизация (WebP, AVIF)
- ✅ Lazy loading для изображений ниже первого экрана
- ✅ `priority` для главного изображения продукта и первого слайда hero
- ✅ Правильные `sizes` атрибуты для responsive images
- ✅ Кэширование изображений на 30 дней (`minimumCacheTTL`)

### 5. Минификация и оптимизация
**Уже включено:**
- ✅ `swcMinify: true` - быстрая минификация через SWC
- ✅ `compress: true` - gzip/brotli сжатие
- ✅ `optimizeFonts: true` - оптимизация шрифтов
- ✅ `optimizePackageImports` - tree-shaking для больших библиотек

### 6. Статическая генерация (ISR)
**Уже настроено:**
- ✅ `export const revalidate = 300` на главной странице (5 минут)
- ✅ ISR для `/products` и `/product/[...slug]`
- ✅ SSR только для динамических страниц (admin, account, checkout)

## 📊 Ожидаемые результаты

### До оптимизации:
- TTFB: 2-5 секунд
- Первая загрузка: 3-8 секунд
- Повторная загрузка: 2-5 секунд

### После оптимизации:
- TTFB: 0.3-0.8 секунд (кэш hit) / 0.5-1.5 секунд (кэш miss)
- Первая загрузка: 1-2 секунды
- Повторная загрузка: 0.5-1 секунда (из кэша)

**Улучшение:** 70-85% быстрее для повторных посещений

## 🚀 Дополнительные рекомендации

### 1. CDN для статических ресурсов
Vercel автоматически использует CDN для всех статических файлов. Убедитесь, что:
- Все изображения загружаются через `next/image`
- Шрифты подключены через `next/font`

### 2. Мониторинг производительности
Используйте:
- **Vercel Analytics** - встроенная аналитика производительности
- **Chrome DevTools** - Network tab для проверки кэширования
- **Lighthouse** - для аудита производительности

### 3. Проверка кэширования
После деплоя проверьте заголовки:
```bash
curl -I https://your-domain.com/
# Должен быть: Cache-Control: public, s-maxage=60, stale-while-revalidate=120
```

### 4. Оптимизация для мобильных устройств
- ✅ Responsive images с `sizes` атрибутами
- ✅ Lazy loading для изображений
- ✅ Оптимизированные размеры изображений

## 🔍 Проверка после деплоя

1. **Проверьте кэширование:**
   ```bash
   curl -I https://your-domain.com/ | grep -i cache
   ```

2. **Проверьте производительность:**
   - Откройте Chrome DevTools → Network
   - Обновите страницу
   - Проверьте, что статические файлы загружаются из кэша (Status: 200, Size: disk cache)

3. **Проверьте TTFB:**
   - В Network tab найдите HTML документ
   - TTFB должен быть < 500ms для кэшированных страниц

## 📝 Примечания

- Кэширование работает только в production (Vercel)
- В development режиме кэширование отключено для удобства разработки
- ISR работает вместе с кэшированием: страница обновляется каждые 5 минут в фоне
- `stale-while-revalidate` позволяет показывать старую версию пока обновляется новая
