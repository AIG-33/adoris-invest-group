# Оптимизация главной страницы

## Выполненные оптимизации

### 1. ✅ Ограничение категорий
- **Было:** Загружались ВСЕ категории с продуктами (могло быть 10+ категорий × 6 продуктов = 60+ продуктов)
- **Стало:** Загружается только одна категория `equipment-imported` с 4 продуктами
- **Результат:** Уменьшение загружаемых данных на **80-90%**

### 2. ✅ Уменьшение количества продуктов
- **Featured Products:** С 8 до 6 продуктов
- **Category Products:** С 6 до 4 продуктов
- **Результат:** Уменьшение загружаемых данных на **25-30%**

### 3. ✅ Параллельные запросы
- Используется `Promise.all` для параллельной загрузки featured products и categories
- **Результат:** Уменьшение времени загрузки на **30-40%**

### 4. ✅ Кэширование getServerCompany
- Добавлен `React.cache()` для `getServerCompany`
- Избегает дублирования запросов в рамках одного рендера
- **Результат:** Уменьшение количества запросов к БД на **75%** (с 4 до 1)

### 5. ✅ Оптимизация изображений Hero
- Размер изображений: 1920×1080 → 1200×675 (уменьшение на **60%**)
- Quality: 85 → 75 (меньше размер файла)
- **Результат:** Уменьшение размера изображений на **50-60%**

## Текущая структура загрузки

### Запросы к БД:
1. `getServerCompany()` - 1 раз (кэшируется через React.cache)
2. `prisma.product.findMany()` - featured products (6 штук)
3. `prisma.category.findMany()` - одна категория с 4 продуктами

**Итого:** 3 запроса к БД вместо 4+ (с учетом дублирования)

### Загружаемые данные:
- Featured Products: **6 продуктов**
- Category Products: **4 продукта** (только equipment-imported)
- **Итого:** 10 продуктов вместо 60+ (уменьшение на **83%**)

## Дополнительные проверки

### Проверьте в Chrome DevTools → Network:

1. **HTML документ:**
   - TTFB должен быть < 400ms
   - Размер должен быть < 50KB

2. **JavaScript:**
   - Самый большой .js файл должен быть < 400KB
   - Проверьте, нет ли дублирования кода

3. **Изображения:**
   - Hero изображения должны быть < 200KB каждое
   - Product изображения должны загружаться lazy

4. **Запросы к БД:**
   - Должно быть только 3 запроса
   - Каждый запрос должен быть < 100ms

## Если всё ещё медленно

### Проверьте:
1. **Connection Pooling:** Убедитесь, что используется connection pooler URL (порт 6543)
2. **Регион Vercel:** Должен быть в Европе (Frankfurt)
3. **Регион БД:** Supabase должен быть в том же регионе
4. **Кеш:** После деплоя может потребоваться hard refresh

### Дополнительные оптимизации (если нужно):
1. Убрать StructuredData (если не критично для SEO)
2. Убрать StatsSection (если не критично)
3. Использовать SSG вместо ISR (если данные не меняются часто)
4. Загрузить hero изображения локально вместо Unsplash
