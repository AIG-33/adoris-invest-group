# Анализ производительности и план оптимизации

## Текущие проблемы производительности

### 1. База данных
- ❌ Много запросов с `include` вместо `select` - загружаются лишние данные
- ❌ Нет индексов на часто используемых полях (slug, domain, featured)
- ❌ Нет connection pooling оптимизации
- ❌ `force-dynamic` везде - нет кеширования на уровне Next.js
- ❌ N+1 запросы в некоторых местах

### 2. Изображения
- ❌ Внешние изображения Unsplash без оптимизации
- ❌ Нет lazy loading для всех изображений
- ❌ Большие изображения загружаются сразу
- ❌ Нет WebP/AVIF конвертации для всех изображений

### 3. Next.js конфигурация
- ❌ Нет ISR (Incremental Static Regeneration) для статических страниц
- ❌ Нет оптимизации bundle size
- ❌ Нет compression для API routes
- ❌ Нет edge caching

### 4. Код
- ❌ Много компонентов загружаются синхронно
- ❌ Нет code splitting для больших компонентов
- ❌ Нет мемоизации для тяжелых вычислений
- ❌ Клиентские компоненты загружаются сразу

### 5. Хостинг (Vercel)
- ⚠️ Vercel может быть медленным для баз данных в других регионах (Dubai)
- ⚠️ Нет CDN для статических ресурсов в регионе пользователя
- ⚠️ Edge functions не используются

## План оптимизации

### Фаза 1: Оптимизация базы данных (Критично - высокий приоритет)

1. **Добавить индексы в Prisma schema:**
   ```prisma
   model Product {
     // ... existing fields
     @@index([featured])
     @@index([categoryId])
     @@index([manufacturerId])
     @@index([slug])
   }
   
   model Company {
     // ... existing fields
     @@index([domain])
     @@index([slug])
   }
   
   model Category {
     // ... existing fields
     @@index([slug])
   }
   
   model Manufacturer {
     // ... existing fields
     @@index([slug])
   }
   ```

2. **Оптимизировать запросы:**
   - Заменить `include` на `select` везде где возможно
   - Использовать `take` и `skip` для пагинации
   - Добавить `where` условия для фильтрации на уровне БД

3. **Connection pooling:**
   - Настроить PgBouncer или использовать Supabase connection pooling
   - Использовать `DATABASE_URL` с параметрами pooling

### Фаза 2: Оптимизация Next.js (Высокий приоритет)

1. **ISR (Incremental Static Regeneration):**
   - Заменить `force-dynamic` на `revalidate` где возможно
   - Использовать `revalidate: 60` для страниц продуктов
   - Использовать `revalidate: 3600` для статических страниц

2. **Оптимизация bundle:**
   - Добавить `experimental.optimizePackageImports` в next.config.js
   - Использовать dynamic imports для тяжелых компонентов
   - Оптимизировать импорты (tree shaking)

3. **Кеширование:**
   - Добавить HTTP headers для кеширования
   - Использовать Next.js cache для API routes
   - Настроить edge caching

### Фаза 3: Оптимизация изображений (Средний приоритет)

1. **Локальные изображения:**
   - Загрузить изображения Unsplash локально
   - Использовать Next.js Image optimization
   - Настроить CDN для изображений

2. **Lazy loading:**
   - Добавить `loading="lazy"` для всех изображений ниже fold
   - Использовать `priority` только для первого изображения

3. **Форматы:**
   - Использовать WebP/AVIF везде
   - Настроить автоматическую конвертацию

### Фаза 4: Оптимизация кода (Средний приоритет)

1. **Code splitting:**
   - Использовать `dynamic()` для тяжелых компонентов
   - Lazy load компоненты которые не нужны сразу

2. **Мемоизация:**
   - Использовать `useMemo` для тяжелых вычислений
   - Использовать `React.memo` для компонентов

3. **Оптимизация компонентов:**
   - Разделить большие компоненты на меньшие
   - Использовать server components где возможно

### Фаза 5: Хостинг (Низкий приоритет - если код не поможет)

1. **Vercel Pro:**
   - Больше ресурсов CPU/RAM
   - Edge functions в регионе пользователя
   - Лучший CDN

2. **Альтернативы:**
   - Railway (лучше для баз данных)
   - Fly.io (edge computing)
   - Self-hosted на VPS (больше контроля)

## Ожидаемые результаты

### После Фазы 1-2 (База данных + Next.js):
- ⚡ Уменьшение времени загрузки на 40-60%
- ⚡ Уменьшение нагрузки на БД на 50-70%
- ⚡ Улучшение TTFB (Time to First Byte) на 50%

### После Фазы 3 (Изображения):
- ⚡ Уменьшение размера страницы на 30-50%
- ⚡ Улучшение LCP (Largest Contentful Paint) на 40%

### После Фазы 4 (Код):
- ⚡ Уменьшение времени интерактивности на 20-30%
- ⚡ Улучшение FCP (First Contentful Paint) на 15%

## Приоритет реализации

1. **Критично (делать сразу):**
   - Индексы в базе данных
   - Замена `include` на `select`
   - ISR вместо `force-dynamic`

2. **Важно (делать в первую очередь):**
   - Оптимизация изображений
   - Code splitting
   - Кеширование

3. **Желательно (делать после):**
   - Мемоизация
   - Edge caching
   - CDN для изображений

4. **Опционально (если не поможет):**
   - Обновление хостинга
   - Self-hosted решение

## Метрики для отслеживания

- **TTFB** (Time to First Byte): < 200ms
- **FCP** (First Contentful Paint): < 1.8s
- **LCP** (Largest Contentful Paint): < 2.5s
- **CLS** (Cumulative Layout Shift): < 0.1
- **FID** (First Input Delay): < 100ms
